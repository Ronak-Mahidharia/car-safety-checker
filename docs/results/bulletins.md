# Results: reading manufacturers' service bulletins

Generated by `scripts/run_extraction.py`. Don't edit by hand.

NHTSA publishes the communications manufacturers send their dealers (23,164 in `TSBS_RECEIVED_2025-2026.zip`, SHA-256 `3002a198debb…`). A local model reads each summary and fills in a form for a driver, with a quote from the summary before every field (`src/carsafety/extract.py`); a field whose quote isn't in the summary isn't shown. NHTSA's own coded fields are the answer key, and the model never sees them: the type (is it a warranty extension? an over-the-air update?), the model years, and the components.

The key (`data/bulletins/`): 20 dev and 50 test communications of each of NHTSA's six types, at random (seed 2026). Dev is what NHTSA added before 2026, test what it added from Jan 1, 2026, and each summary is used once. Because every type is sampled equally, the warranty precision is also estimated over all of the split's communications, weighing each type by how many it has.

### Read one by one: the symptom and the fix in 40 test forms

Each form as shown, after the evidence check. Symptom: right when it says, in plain words, what the summary says a driver may notice; wrong when it isn't that (not in the summary, or something only a technician sees); rightly empty when the summary says nothing a driver notices; wrongly empty when it does and the form shows nothing. Fix: right when its kind fits the remedy the summary states; wrong when it doesn't; rightly empty (not stated) when the summary states no remedy; wrongly empty when it does and the form shows not stated.
